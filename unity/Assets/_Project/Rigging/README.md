## SK_VillagerNPC.fbx
Kampung villager NPC, 1292 tris, one material `M_Villager_Palette` (`Textures/T_Villager_Palette.png`,
64x64 flat swatches; recolour a villager by duplicating the PNG). Feet at the origin, faces +Z.

Import settings (Rig tab): **Animation Type = Humanoid**, Avatar Definition = Create From This Model.
Bone names are Unity's own (`Hips, Spine, Chest, Neck, Head, Left/RightShoulder, UpperArm, LowerArm, Hand,
UpperLeg, LowerLeg, Foot`), rest pose is a T-pose, so auto-mapping needs no fixes. No fingers / toes.

Animation tab, clips (30 fps):

| Clip | Length | Loop Time | Notes |
|---|---|---|---|
| `Idle` | 2.5 s | on (Loop Pose on) | breathing, weight sway, head look |
| `ThrowTrash` | 1.5 s | off | right-hand toss forward; **release at 0.53 s (frame 16)** |
| `CarryBin` | 1.0 s | on (Loop Pose on) | walk in place holding a bin in front; paced for ~0.75 m/s, Root Motion off |

Props (separate FBX, same palette):
- `SM_Villager_TrashBag.fbx`: parent under bone `Socket_RightHand` with **localPosition 0, localRotation 0**
  at the start of `ThrowTrash`; at 0.53 s unparent it (or hide it and spawn a `PF_Trash_*` prefab at its
  position) and give it a forward / up velocity. Any trash prefab can use the same socket instead.
- `SM_Villager_Bin.fbx`: parent under `Socket_Carry` (child of `Chest`) with zero local transform for
  `CarryBin`; both hands sit on its rim.

Both sockets have an identity rest frame in Unity, so props need no rotation offset.

## Anim_PlayerToolSwing.fbx
First-person swing clips. Hierarchy: `ToolSwingRig` (root) > `ToolHolder`, both identity at rest
(no -90 deg X: the rig is pre-rotated in Blender). No mesh.

Import: **Animation Type = Generic**, Avatar = Create From This Model, Root node = None, Loop Time off.

| Clip | Length | Motion (camera space) |
|---|---|---|
| `SerokanScoop` | 0.8 s | small pull back, net dips forward-down, drags, lifts high, back to rest |
| `GancoHookSwing` | 0.7 s | hook raised overhead, strikes forward-down, yanks back toward the player |

Use:
1. Drop the FBX model under the camera's `ToolSocket` (local position / rotation 0) and add an `Animator`
   on its root with a small controller: an empty default state plus the two clips, triggered on scoop.
2. Instantiate the equipped `PF_Tool_*` under **`ToolHolder`** (instead of `ToolSocket`) with the same
   localPosition 0 / localRotation `Euler(65, -8, 0)` that `KaliPlayerController` uses today.
3. Use `SerokanScoop` for the serokan / net / scoop tools and `GancoHookSwing` for hooks, sickles, rakes.
   The clips start and end at rest, so they can cut back to the empty state.
4. `KaliPlayerController` currently also rocks `ToolSocket.localRotation` (procedural 32 deg swing); disable
   that when the Animator drives the swing, or the two motions add up.
