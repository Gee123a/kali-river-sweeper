## Anim_PlayerToolSwing.fbx
First-person swing clips. Hierarchy: `ToolSwingRig` (root) > `ToolHolder`, both identity at rest
(no -90 deg X: the rig is pre-rotated in Blender). No mesh.

Import: **Animation Type = Generic**, Avatar = Create From This Model, Root node = None, Loop Time off.

| Clip | Length | Motion (camera space) |
|---|---|---|
| `SerokanScoop` | 0.8 s | small pull back, net dips forward-down, drags, lifts high, back to rest |
| `GancoHookSwing` | 0.7 s | hook raised overhead, strikes forward-down, yanks back toward the player |

Use:
1. Drop the FBX model under the camera's `ToolSocket` (local position / rotation 0) and add an `Animator`
   on its root with a small controller: an empty default state plus the two clips, triggered on scoop.
2. Instantiate the equipped `PF_Tool_*` under **`ToolHolder`** (instead of `ToolSocket`) with the same
   localPosition 0 / localRotation `Euler(65, -8, 0)` that `KaliPlayerController` uses today.
3. Use `SerokanScoop` for the serokan / net / scoop tools and `GancoHookSwing` for hooks, sickles, rakes.
   The clips start and end at rest, so they can cut back to the empty state.
4. `KaliPlayerController` currently also rocks `ToolSocket.localRotation` (procedural 32 deg swing); disable
   that when the Animator drives the swing, or the two motions add up.
